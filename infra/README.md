# Production deployment preparation

Use a dedicated Linux VM. Install Docker Engine, Python 3 venv and Caddy from trusted OS/vendor repositories, then pull `python:3.12-slim` before starting. Create a dedicated `escape` system account in the Docker group: this controller has host Docker privileges; sandbox containers never receive its socket. Place a reviewed release under `/opt/agent-escape-room/releases/<version>` and point `/opt/agent-escape-room/current` to it. Create `/opt/agent-escape-room/venv`, install pinned/reviewed dependencies from infra/requirements.lock.txt, and create `/var/lib/agent-escape-room` owned by escape. Copy the environment example to `/etc/agent-escape-room.env`, mode 0600, fill inference key, model and strong random operator token on the VM only. Preserve that file and the SQLite database across releases.

Install `agent-escape-room.service` in `/etc/systemd/system`; systemctl daemon-reload, enable and start. Install Caddyfile with a valid `ESCAPE_DOMAIN` in Caddy's systemd environment; Caddy must serve HTTPS before an operator enters a token. Firewall permits SSH, 80 and 443; backend binds loopback. Verify `/healthz`, TLS, config, demo report, unauthorized POST rejection, Docker cleanup and logs without secrets. Access to Docker group is effectively host root; isolate VM accordingly.

Budgets are lifetime counters in SQLite. Each accepted run reserves one run; each attempted provider request reserves one call and 1024 maximum output tokens before dispatch, including failed requests. Input is character bounded, not token-metered. Limits do not estimate USD or cover VM/network costs. Never delete/reset the database to circumvent budget; change caps deliberately. One uvicorn worker is required for concurrency and in-memory rate enforcement. Proxy trust must contain only the local Caddy addresses; Caddy overwrites forwarded headers according to its own trusted proxy policy.

For rollback stop service, repoint `current` to the previously reviewed release, and start it; preserve database and environment. Startup and shutdown remove only Docker resources bearing the controller ownership label, and refuse startup when inventory/cleanup cannot be confirmed. Old pre-label resources require manual inspection. Review logs and validate health; rollback does not reverse provider spend.
